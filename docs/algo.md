# 算法说明与对比实验（负责人：P4，算法或实验有变动时更新）

## 1. 四项特色功能

| 功能 | 实现 | 参数 | 输出 |
|---|---|---|---|
| 人物最短路 | Cypher `shortestPath`，跳数最少 | from / to | 节点序列 + 跳数 |
| 加权最短路 | 代价 `cost = 101 - weight`，Dijkstra（GDS 优先） | from / to / mode=weighted | 节点序列 + 总代价 |
| 影响力排序 | GDS PageRank，装不上时退化为度数近似 | limit | 人物 + 得分 |
| 阵营社区发现 | GDS Louvain | 无 | 社区编号 + 成员 |
| 小世界验证 | 抽样计算平均最短路径与聚类系数 | sample | avg_path / clustering |

## 2. 关键参数与理由

- 最短路搜索上限 `*..6`：三国的"六度"经验值，超过 6 跳的路径对展示没有意义，且能防止大图上查询失控；
- 加权代价用 `101 - weight`：把"关系越强越近"转成"代价越小"，保证 Dijkstra 的正权要求；
- 社区发现不做人工指定阵营：结果与史实阵营的差异本身是答辩素材（"算法看关系密度，人看史书"）。

## 3. 与关系型数据库的对比实验

| 查询 | MySQL 写法 | 耗时 | Neo4j 写法 | 耗时 |
|---|---|---|---|---|
| 一跳邻居 | `JOIN relations ON ...` | 待填 | `MATCH (p)-[r:RELATED_TO]-()` | 待填 |
| 两跳关系 | 两次自连接 | 待填 | `*1..2` | 待填 |
| 最短路（3 跳内） | 递归 CTE + 层数控制 | 待填 | `shortestPath` | 待填 |
| 影响力排名 | 反复聚合，需手写迭代 | 待填 | GDS PageRank 一行 | 待填 |

测法：同一份数据、同一台机器、预热后取 10 次中位数。测完把表填上，这张表是"为什么用图数据库"的唯一硬证据。

## 4. 局限

- GDS 装不上时降级为近似算法，报告中如实说明；
- 图规模只有数百节点，绝对耗时的差距不如"写法复杂度"的差距有说服力，陈述时说清这一点。

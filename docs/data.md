# 数据说明（负责人：P1，数据有变动时更新）

> 本文是答辩"数据"章节的底稿：**数据从哪来、怎么变成图、质量怎么保证、有哪些已知缺陷**。
> 所有数字都可用 `scripts/` 下四个脚本复现，不是估算。

## 1. 语料来源与切分

| 项 | 内容 |
|---|---|
| 文本 | 《三国演义》一百二十回（公版书，简体） |
| 获取 | 经 jsDelivr CDN 取 GitHub 开源整理版（`hachiam/text-data-mining` 的 `sanguo-utf8.txt`），UTF-8 |
| 规模 | 599,996 字（含标点），120 回，平均 4,970 字/回 |
| 存放 | `data/raw/sanguo_full.txt` + `data/raw/chapters/ch001.txt … ch120.txt`（不入仓库，群共享目录 `语料/`） |

切分由 `scripts/split_chapters.py` 完成：

1. 回目行正则同时兼容 `第X回` 与 `正文 第X回`（该语料自带"正文"前缀，最初一版正则因没考虑前缀而切出 0 回，已修）；
2. 中文数字转整数保留 `cn_to_int()`，但**回目号按出现顺序重排为 1—120**，防止原文偶有缺号导致洞；
3. 每回单独落一个文件，首行为标准化的 `第X回 回目`，正文原样保留（含全角空格缩进，不做清洗）；
4. 脚本校验回数必须等于 120，否则返回非 0——**不允许静默产出残缺语料**。

首回"宴桃园豪杰三结义 斩黄巾英雄首立功"、末回"荐杜预老将献新谋 降孙皓三分归一统"，两端齐整即视为语料完整。

## 2. 抽取规则

`scripts/extract_mentions.py` 三步：

1. **词典匹配**：以 `persons.csv` 的 `name` + `aliases` 为键，在每回正文中找出现；
2. **单遍最长匹配**：把全部别名按长度降序拼成一条正则，一次扫描。这解决了两个坑——
   同一位置长名优先（`张翼德` 归张飞，不会再被 `张翼` 抢走半截），且命中后不重复计数
   （旧实现用 `body.count(alias)` 逐个别名统计，`张翼德` 会同时给张飞和张翼各记一次）；
3. **共现**：同一回内两人同时出现即记一次共现，`count += min(两人在本回的出现次数)`；
   归一化到 1—100 后写入 `data/build/cooccurrence.csv`，共 **7,798 对**候选。

同一遍扫描还顺带产出 `data/build/mentions.csv`（`chapter,person,count`，共 2,552 条），
即每回每个人物出现几次。P2 的导入脚本据此建 `APPEARS_IN` 边，"这个人在哪几回出现"
才查得出来——共现表只有配对，撑不起单人时间线。

共现只产生"候选关系"，`type` / `evidence` / `confidence` 全部人工标注后才进 `relations.csv`。

## 4. 置信度判定标准

| 区间 | 判定依据 | 典型例子 |
|---|---|---|
| 0.95—1.0 | 原文直接陈述（结义、父子、拜师、明确归降） | 刘关张 0.98；刘备—刘禅 0.98 |
| 0.85—0.95 | 多处情节强支撑（长期同阵营、共同征伐、受禅继位） | 曹操—张辽 0.95；孙权—周瑜 0.98 |
| 0.70—0.85 | 单一情节或史实推断（同朝为将、荐贤） | 皇甫嵩—董卓 0.74；司马徽—诸葛亮 0.84 |
| 0.60—0.70 | 程序推定（阵营归属、同阵营共现），仅作骨架 | 归属推定边 0.60；同僚补边 0.66 |

人工边平均置信度 **0.899**，程序边 **0.633**——两条线分开统计，答辩时能直接说明"哪些是人读出来的，哪些是推出来的"。

## 5. 质检结果

**格式质检**（`extract_mentions.py --validate`）：列名、枚举、外键、重复边、自环、孤立点全部通过，**0 问题**。
179 人无一孤立节点（`relations.csv` 覆盖 179/179）。

**证据核对**（`check_data_quality.py`）：把 333 条 `evidence` 逐条回原文，检查三件事——
回目号是否存在、`evidence` 里写的回目名是否真是那一回的、两人是否真在该回出场。
结果 **0 错误**。

这一步比方案要求的"抽 10% 人工核对"更严：**100% 机检 + 情节描述抽检**。机检查不出的只有
"回目对、两人都在、但情节描述写错了"这一类，这部分靠人工抽检覆盖。

**权重一致性**：事件级标注边（172 条）的 `weight` 与共现强度 Spearman ρ = **0.54**。
正相关但不重合是刻意的——共现频次高的未必关系重（刘备—曹操共现 72 回，是全书最大的一对"敌人"），
而亲族、父子往往同场极少（孙坚—孙权共现仅 1 回，但 unquestionably 是父子）。

**抽检结论**：

| 批次 | 样本 | 方式 | 结果 |
|---|---|---|---|
| 机检 | 333 / 333 | `check_data_quality.py` 逐条回原文 | 修掉 8 条证据回目错误（详见下），复查后 0 错误 |
| 人工抽检 | 12 条（seed=20261126） | `check_data_quality.py --sample 12` 打印该回同现原句，人读判断 | 12 条情节描述均与原文相符，0 条需改 |

机检阶段修掉的 8 条，错误类型都是"回目选错、对方不在该回出场"，例如
孙权—曹操原标第 48 回（宴长江赋诗，孙权不在场），改为第 44 回（孙权决计破曹操）；
太史慈—孙策、刘焉—刘璋、朱儁/皇甫嵩—董卓等同理。这类错误人工翻书很难发现，
正是写这个脚本的原因。

抽样命令（任何人可复现）：

```bash
python scripts/check_data_quality.py --sample 12 --seed 20261126
```

## 6. 已知问题清单

| 编号 | 问题 | 影响 | 处理方式 | 状态 |
|---|---|---|---|---|
| D-01 | 同名不同人（张温：董卓朝太尉 / 孙权朝中大夫；马忠：蜀将 / 吴将） | 若都收录会把两人生平混在一条记录 | 只保留主线人物那一位，弃收易混者（张温、吴马忠已剔除） | 已处理 |
| D-02 | 子名的连带命中（`张翼德` ⊃ `张翼`） | 张翼出现次数虚高 | 改单遍最长匹配，长名优先 | 已处理 |
| D-03 | 表字作别名有歧义（`子明` 既是吕蒙又是孙亮；`公明` 既是徐晃又是管辂；`子远` 是许攸与吴懿） | 会把两人提及合并 | 歧义表字一律不进 aliases，宁缺不错 | 已处理 |
| D-04 | `卧龙`、`后主` 这类称呼兼有地名/身份义 | 少量误命中（卧龙岗） | 保留（收益大于损耗），在置信度上体现 | 接受 |
| D-05 | 孙夫人（孙尚香）阵营记为蜀，但她兄是孙权、最终归吴 | 前端按阵营筛选时归属可争议 | 记蜀（随夫），在答辩中说明 | 接受 |
| D-06 | 孙刘关系只能记一种类型：前期联盟、后期夷陵相攻 | `type=敌对` 无法表达"先盟后敌" | 单边模型限制，取后期主要冲突；如 P2 加时间维度可拆两条 | 待 P2 决策 |
| D-07 | 62 人无别名（多为仅出场一两次的次要人物，如大乔、小乔、胡车儿） | 换称呼时召回缺失 | 该类人物原文基本只用姓名，影响可忽略 | 接受 |
| D-08 | 生卒年仅 47 人齐全 | 时间线页面信息稀疏 | 史书无载即留空，不臆造 | 接受 |
| D-09 | 21% 的边是阵营归属推定，非原文情节 | 答辩可能被追问"凭什么" | evidence 明写"按阵营归属推定"、confidence 0.6，可一键筛掉重算 | 接受 |

## 7. 给下游的说明

- **P2（建库）**：`relations.csv` 的 `source < target` 已按 Unicode 排序去重，可直接 `MERGE`；
  事件里的 `place` 共 51 个，直接当 `Place.name` 建唯一约束。
- **P4（算法）**：如果只想要"有情节依据"的子图，过滤 `evidence NOT LIKE '%推定%' AND evidence NOT LIKE '%同阵营共现%'`
  可得 172 条纯人工边；全量 333 条密度更适合社区发现。
- **P5（前端）**：默认展示建议 `weight >= 60`（153 条），否则 179 个节点的图会糊成一团。
- **演示脚本**：搜索"玄德"能命中刘备、"卧龙"能命中诸葛亮、"美髯公"能命中关羽，
  这三个别名为答辩必测项，改动 `persons.csv` 时不要动它们。
